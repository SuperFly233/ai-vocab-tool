# Fushi → Anki 联动：发布后只读调查与下一轮方案

调查时间：2026-10-21，v0.30.0 发布及生产验收之后。本文是下一轮规划，不是联动已上线的声明。

## 调查结论（公开脱敏版）

- 只读调查范围为应用安装、字段映射、媒体组织和可用连接；不在仓库记录个人路径、牌库名称、账号、配置值或媒体清单。
- 当前没有完成可用连接的端到端握手，因此后续必须先明确目标与连接方式，不能直接宣称可自动发送或云同步。
- 字段映射需要区分词条、释义、原句、图片、音频与来源；应用内部模型 ID 与外部笔记类型 ID 不可直接互换。
- SQLite immutable/read-only 查询不读取 WAL 中的新提交，只能作为基础文件快照，不能代替运行时接口确认。
- 模板正文仍需通过受支持的接口读取并预览；本次不对现有模板做解码覆盖。视频嵌入及终端播放必须单独验收。
- 同步辅助程序存在不等于当前启用了云同步，不能用安装状态代替实际同步验收。

## 三个主题，各 6 项

### 一、修复与可靠性：本地连接及数据安全

以下是待验证/修复单元，不预先计为 6 个已确认 bug。

1. 明确实际写入目标：Fushi 内部集合还是桌面 Anki，不能混用两个本地模型 ID。
2. 排查配置目标的拒绝或异常响应；只用只读 API 做握手，确认具体服务及当前牌库。
3. 明确账号、目标牌库与模板变更后的连接隔离；不将旧任务写入新目标。
4. 验证连接中断、应用退出、重试和超时后的幂等性，不重复建卡。
5. 媒体按内容哈希校验、失败独立恢复，传输成功不等同于笔记创建成功。
6. 写入前保留原值和操作日志，撤销只作用于本次创建/更新，不删除其他卡片或覆盖后续学习修改。

### 二、优化：场景到卡片的转换质量

1. 使用 v0.30 学习清单作为输入，预览后选择场景、关联词条及义项，不把整个词条原样堆进一张卡。
2. 原句、译文、高亮、核心义分别映射；关联级高亮不能变成共享场景全局高亮。
3. 词头用 AI 校正标题，Origin 作为来源信息保留；不改写现有词典定义字段。
4. 复用已有图片/音频字段，视频单独验证模板和终端支持，不能未经验证替换成伪可播放链接。
5. 来源、章节、时间及笔记整理进入用户明确选择的字段；保留原有字段内容。
6. 按目标模板验证预览与实际卡面一致，先在专用测试牌库检查桌面和手机，不直接改已有模板。

### 三、新增：可控的发送与联动

1. 场景/关联词条的“发送到 Anki”选择面板，牌库和字段映射可预览确认。
2. 本地桥接接收经过授权的导出清单；生产网页不默认直连开放的本机端口或上传本地认证信息。
3. 用 groupId + 词条 ID + 目标身份生成稳定来源键，保存目标 note ID，支持后续定向更新。
4. 批量发送预览、逐项进度、跳过重复项与失败重试，不能把部分失败报成全部成功。
5. 可选择读取真实学习结果做展示；Lexi 的三态标记不擅自写入 Anki 调度参数。
6. 单独评估云端 outbox → 本地桥接 → Anki 同步链路。只在端到端验证后提供自动化开关，不把本地建卡称为自动云同步。

## 下一轮进入条件

先确认实际目标与可用本地接口，再读取运行时模板及牌库；写入阶段先用专用测试牌库，经明确授权再进入真实牌库。
本轮没有安装插件、启动 Anki、修改端口/CORS、写入数据库、调整模板或同步真实卡片。也没有新建后台自动化。
