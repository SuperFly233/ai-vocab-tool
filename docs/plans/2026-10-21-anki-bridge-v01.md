# Anki Bridge 0.1 / Lexi v0.31.0 预备版验收

## 结论与边界

本轮实现独立云任务、网页制卡入口和 Windows 本地伴侣程序。生产采用默认关闭开关；这不是已贯通的手机 → 真实 Anki 云链路。
用户已确认当前没有数据库管理通道，迁移留待后续一起配置。当前本机只读诊断也未获得兼容的 AnkiConnect 连接；没有自动启动 Anki、安装插件、修改 Fushi 或写真实牌库。

统计：可靠性 6、流程优化 6、新增 6，共 18 个验收单元；不是宣称修了 6 个既有 Bug。
其中 15 项实现完成并通过本地/隔离验收，3 项部分完成、待生产或终端验收。以下“完成”均限定这一范围；完整真实端到端验收尚未通过。

## 测试与产物

- `npm run check`：既有版本、历史、设置、存储、队列、同步、媒体 API 全部通过。
- `node scripts/check-anki-jobs.cjs`：PGlite 实际 PostgreSQL 引擎迁移、RLS、原子去重/租约、过期、取消、重试、撤销及 API 关闭开关测试通过。
- Python unittest：12 项通过，涵盖 HTML/链接、来源隔离、回执丢失、并发编辑、学习后保护、更新撤销、素材完整性、确认、本地跨站保护、专用模板协议及凭据不落明文。
- `check-anki-ui.cjs`：网页 320/390/768/1024/1440 明暗主题；伴侣 390/1440 明暗主题，通过无溢出、快照、回执、关闭开关、本地刷新与连接表单检查。
- 既有 scene-workspace、scene-learning、scene-media、delete-undo UI 测试通过。
- 截图保存在本机忽略目录 `tmp/anki-bridge-qa/screenshots/`，不会发布测试账号或私有数据。
- 打包采用项目内官方 Python 3.12.10 隔离运行时，系统旧 Python 3.12.4 的打包崩溃不通过替换系统软件处理。EXE `--self-test` 验证实际本地 HTTP 启动、资源和 CSRF 后退出。
- 系统凭据管理器以随机、非秘密临时项完成写入/读取/删除验证，不读取既有密码；无明文降级。
- 运行依赖完整锁定，打包器许可证例外和第三方许可证随测试包交付；未打包 Anki/Fushi 源码。测试包未签名。

## 后续配置门槛

1. 用户登录其 Supabase 管理项目后，由可用管理通道在目标项目执行 `integrations/anki-bridge/migration.sql`；不要把数据库密钥贴进聊天或 Git。
2. 验证两个隔离账号的任务权限、设备领取及必要素材；现有 study_store 不迁移、不重写。
3. 启动真实 Anki 并验证现有插件接口。先在专用测试牌库用无私人内容的图片/GIF测试完整链路；真实牌库必须再明确确认。
4. 满足以上验收后才设置 Cloudflare `ANKI_BRIDGE_ENABLED=true` 并重新部署；之前应稳定返回 503 / enabled:false。
5. 手机确认真实回执后，才可称此路线可用；Anki 自身同步需独立验证，之后再进入 Fushi 接口适配。
