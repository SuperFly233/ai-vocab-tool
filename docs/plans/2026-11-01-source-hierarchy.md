# v0.45.0 Source Hierarchy

Approved: stable work IDs/canonical names/aliases, optional two child levels,
automatic reuse in the existing scene pipeline, first unknown work confirmed once
without blocking capture. Time is a scene locator, not a folder. Existing learning
folders remain independent. Old scenes are not merged or deleted.

Reference source-hierarchy-0450-reference.png: adopt scoped expandable work/path
groups and aligned bottom-border fields, compact one-work confirmation; reject
invented tasks, media/audio controls and mandatory source/time fields. Actual names
and counts must come from the account's records. No screenshot background.

Use existing authenticated source RPC/catalog and account-isolated LearningStore
cache. Add scoped child nodes and optional sourcePath to scenes, preserve legacy
text and new fields through sync/backup. AI may suggest existing directory IDs but
never create/rename canonical records. Unknown work proposals remain source clues
until one explicit confirmation. Same batch/known alias hints coalesce; ambiguity
is not a reason to guess or block save. Chapter creation needs supplied/visible
evidence, not merely the previous capture's chapter.

Audit/isolate the previously unapplied source migration first. Apply only additive
schema after SQL auth/revision/collision tests. Enable production only after private
API verification. Browser and PGlite tests use synthetic content. No model/provider,
Anki, Bridge, FSRS or Teyvat corpus expansion is implied.

Acceptance: alias variants/same-name different works/two-level chapter identity,
first-work confirmation shared by repeated scenes, private account isolation and
concurrent confirmation, manual overrides, old backup omission, guarded bulk Undo,
continuous save/background jobs, five widths/themes and unchanged media budget.
