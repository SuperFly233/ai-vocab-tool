# Vercel Deployment Investigation

## Scope

The user subsequently deferred Vercel investigation and selected Cloudflare as
the release target. No integration was disabled, paid plan purchased or dashboard
setting changed. Vercel is not claimed healthy.

## Confirmed

- GitHub commit statuses report failed main deployment `4b0642b` and preview
  `fc0b6a5`. The status supplies deployment links, not the underlying build error.
- The deployment/event API requires authentication (403 without token).
  Browser access was unavailable. No token was requested or written to disk.
- The repository had thirteen JavaScript files under `api`, including three
  helper modules without default HTTP handlers. Moved relay to `server/relay.js`
  and imported the existing shared stream/error modules directly. Ten actual
  HTTP endpoints remain. Cloudflare adapters continue importing the same handlers.
- Added missing `/exercise` and `/account` Vercel rewrites and regression checks.
- `check-vercel-layout.cjs` imports every endpoint and enforces real handlers and
  the direct-function count limit. Included in `check:contracts`.

The helper layout is an actual deployment defect/risk, but the historical failure
cause remains unconfirmed until Build Logs are available. Local tests are not
proof of a successful Vercel deployment.
